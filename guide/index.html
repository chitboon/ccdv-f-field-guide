3. The 8 Blueprint Domains (Technical Invariants)

Domain 1: Agents and Workflows (14.7%) →

Autonomous loops branch strictly on stop_reason, never on text presence. In parallel tool execution, the model halts on stop_reason: "tool_use"; the client executes all tools and responds with a single user turn bundling all tool_result blocks. In supervisor-worker hierarchies, workers return concise summaries, not full raw transcripts.

Domain 2: Applications and Integration (33.1%) →

The Messages API is completely stateless. The client SDK provides typed error mapping, retries (default max_retries=2), and SSE event parsing, but SDK version pinning cannot force Anthropic servers to accept retired parameters. SSE connections are not resumable. Handle 429 using the integer retry-after header. Manage session state externally; enforce multi-tenant isolation structurally in data architecture.

Domain 5: Model Selection and Optimization (16.8%) →

Quality first: Validate task viability on the highest capability model first, then optimize down on cost and latency while measuring against the baseline. Prompt caching requires minimum prefixes (~512–4,096 tokens), supports max 4 breakpoints, has a 5-minute hit-refreshing TTL, and charges 1.25× write with a 90% read discount. Notice: cache_creation_input_tokens and cache_read_input_tokens report outside input_tokens.

Domain 6: Prompt and Context Engineering (11.0%) →

Wrap background reference material in XML tags (<policy_docs>) and place instructions at the very bottom to leverage recency attention weighting. Use affirmative phrasing. Assistant prefilling is retired (returns HTTP 400); enforce JSON using tool schemas or structured outputs. Sanitize inputs via structural delimiting rather than character escaping.

Domain 8: Tools and MCPs (10.6%) →

Tools require name, description, and input_schema. The natural language description is the semantic specification that tells Claude when and why to invoke a tool; strict: true validates syntax only. Request-level tool_choice can force a tool. MCP primitives include Tools (actions), Resources (readable data), and Prompts (templates), transmitted over stdio (local) or HTTP/SSE (remote).

Domain 7: Security and Safety (8.1%) →

Indirect prompt injection arrives in untrusted third-party data. Insecure Output Handling (OWASP LLM02) occurs when model output is rendered unescaped into HTML or shells; solve it via output-side context-aware escaping, not input prompt filters. PreToolUse hooks block destructive commands before execution; PostToolUse hooks redact PII/secrets after execution.

Domain 3: Claude Code (3.1%) →

CLAUDE.md provides standing repo memory, merging hierarchically from root to subdirectories. Settings precedence: Enterprise > Project (.claude/settings.json) > User (~/.claude/settings.json). Non-interactive pipelines use headless print mode (claude -p). MCP configs in .claude/mcp.json expand environment variables via ${VAR}.

Domain 4: Eval, Testing, and Debugging (2.6%) →

Use deterministic code assertions (JSON schema, Pydantic, regex) for structured fields; use LLM-as-a-Judge with concise-rewarding rubrics for open-ended text. Perform boundary tracing across system layers before changing prompts. Detect silent truncation by asserting stop_reason != "max_tokens".

4. The 12 Trap Patterns

Our field research identified 12 high-frequency cognitive traps tested across the blueprint. Read the full 12 Trap Patterns Deep-Dive →

  1. Text Presence vs. stop_reason: Prose is never a stop signal; loops must continue on tool_use and exit only on end_turn.
  2. OWASP LLM02 vs. Prompt Injection: Unescaped output rendered in the DOM is an output-side flaw requiring entity escaping at render time.
  3. Pre vs. Post Hook Timing: PreToolUse blocks arguments before execution; PostToolUse redacts PII/secrets from output after execution.
  4. Tool Runner vs. Agent SDK vs. Managed Agents: Tool Runner has no built-in tools; Agent SDK ships dev tools self-hosted; Managed Agents supplies hosted containers.
  5. SDK Version Pinning vs. Server Deprecation: Client pinning cannot force server acceptance of retired parameters.
  6. Tool description vs. strict: true: strict: true checks schema validity; natural language description governs semantic applicability.
  7. Structural Multi-Tenant Isolation vs. Prompt Prefixes: Enforce tenant boundaries via separate message arrays and cache keys, never in-prompt text tags.
  8. Quality-First Model Selection: Validate feasibility on flagship capability first; treat latency/cost limits as candidate filters.
  9. Parallel Tool Bundling: Return a single role: "user" turn with all tool_result blocks, never consecutive user messages.
  10. Usage Counter Accounting: cache_creation_input_tokens and cache_read_input_tokens report outside input_tokens.
  11. Silent Truncation: stop_reason == "max_tokens" indicates an abrupt cutoff requiring larger ceilings or continuation.
  12. Batch API Ordering: Results return unordered; match requests to results using custom_id.

6. FAQ & Test Day Strategy

How should I pace myself during the 120-minute exam?

With 53 questions, you have roughly 135 seconds per item. If your form features concise 3–4 sentence stems, you can comfortably finish Pass 1 in 50–60 minutes. Flag difficult questions and return to them during your remaining hour.

Are deprecated features like assistant prefilling tested?

On current Claude models, assistant prefilling and temperature with thinking return HTTP 400. In our sitting, neither new adaptive parameters nor deprecated legacy features were asked. Prepare against the official blueprint standards.

What is the difference between CCDV-F and CCAR-F?

CCDV-F (Developer Foundations) focuses heavily on application integration, API mechanics, streaming SSE, tool execution loops, and session state. CCAR-F (Architect Foundations) tests enterprise orchestration, governance, and high-level workflow trade-offs with longer vignettes.
